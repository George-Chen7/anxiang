安响

安响演示社区网格员如何核实独居老人的居家风险。例如，活动传感器在 09:10 记录到高度骤降，到 09:12 仍未观察到起身信号。工作台将这条模拟事件标为「疑似跌倒」，网格员可以查看依据、联系住户、安排上门，并记录核实结果。

社区、住户和设备信号均为虚构。告警等级用于演示处置流程，实际识别效果和响应时间仍需验证。

## 启动本地完整版

在仓库根目录执行以下命令，或在 Windows 上双击启动脚本。Python 服务使用标准库，仓库已包含三维场景依赖和住户卡片构建产物。

```bash
python web/server.py
```

服务在 `127.0.0.1` 的 8765 至 8775 端口中选择可用端口，并打开欢迎页。点击「进入登录」，选择角色并填写对应账号。浏览器没有自动打开时，使用终端打印的地址。首次启动会创建 `web/anxiang.db`，后续启动继续使用该数据库。

| 本地演示角色 | 账号 | 密码 |
| --- | --- | --- |
| 平台管理员 | `admin` | `admin123` |
| 社区网格员 | `grid` 或 `grid2` | `grid123` |

**管理员**可以在「事件模拟器」选择住户、告警等级和接收人，查看事件时间线，并撤回模拟事件。模拟器提供疑似跌倒、异常长时间静止、住户主动求助、燃气、烟雾、用水、消防通道和门磁八类场景。

**网格员**可以在「我的处置」认领公共事件，或处理指派给自己的事件。体验持续跟进时，可按以下顺序操作：

1. 在「待接收」打开一条告警，查看设备依据，接收事件并记录联系情况。
2. 若仍需核实，选择「记录结果 / 跟进」和「需持续跟进」，填写说明及下次跟进时间。刷新后，任务仍在负责人的「处理中」。
3. 再次核实时，可以更新跟进时间、安排上门，或填写最终结论并办结。联系、跟进和结案记录都能在事件时间线中查看。

从旧版升级时，曾以「需持续跟进」结论办结的事件会恢复到「处理中」，原有处置记录保留。旧记录缺少下次跟进时间时，页面显示「待补登记」。

## 本地账号注册与授权

本机维护者先在仓库根目录签发首个管理员邀请码：

```bash
python web/server.py --issue-admin-invite
```

1. 复制终端输出的邀请码，启动本地完整版，在登录页展开「使用邀请码注册账号」，选择「平台管理员」并完成注册。
2. 用新管理员账号登录，在「账号授权」选择要授予的角色，生成邀请码并交给申请人。每个邀请码绑定一个角色，24 小时内可使用一次。
3. 申请人在同一套本地服务中选择对应角色注册。受邀管理员可以继续发码，网格员可以接收和处置事件。公开演示账号仅供体验业务流程，不能签发邀请码。

账号、邀请码和处置记录随本机数据库保存。WorkBuddy 云端版使用独立的演示登录。
