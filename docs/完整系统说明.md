## 一、项目概览

一个带三维社区模型（Three.js）的告警处置系统，由两个角色协作：

- **平台管理员**手动模拟触发各类异常事件，系统发出告警并指派网格员；
- **社区网格员**接收事件，依次完成联系住户、安排上门、记录处理结果，形成闭环；
- 全程留下处置时间线与平台操作日志，可在处置记录中回溯。

项目最初是纯静态演示页面，现已升级为 **Python 服务端 + SQLite 持久化 + 服务端会话鉴权** 的可用版本。

## 三、当前技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Python 3.13 标准库 `http.server.ThreadingHTTPServer`，零第三方依赖 |
| 数据库 | SQLite 3.53（WAL 模式），库文件 `web/anxiang.db` |
| 认证 | PBKDF2-SHA256 / 120000 轮 / 随机盐；服务端 `sessions` 表 + HttpOnly、SameSite=Lax Cookie |
| 接口 | REST `/api/*`，JSON；所有写操作按角色鉴权 |
| 前端 | 原生 JavaScript + Three.js；`api.js → store.js → auth.js / console.js` 分层 |
| 子应用 | `profile-card/`（Vite + React），以 iframe 形式提供住户简介 |
| 实时同步 | 写操作后重拉快照 + 2.5 秒轮询比对数据指纹 |

选择 Python 标准库而非 Flask / Express，是为了双击 `bat` 即可运行，不需要 `pip install` 或 `npm install`。

## 四、功能说明

### 平台管理员

- 异常事件模拟器：7 类场景（燃气、烟雾、跌倒求助、独居关怀、用水、消防通道、门磁），可选楼栋 / 单元 / 楼层 / 房号、告警等级、关联住户档案、指派网格员，一键发出告警。
- 触发后事件实时出现在三维模型、告警列表与网格员待办中；可撤回模拟事件、重置演示数据。
- 查看全量处置记录、处置时间线与平台操作日志。

### 社区网格员

- 事件队列按「待接收 / 处理中 / 已办结」分组，支持从公共事件池认领。
- 四步处置：接收事件 → 记录联系住户（方式、结果、说明）→ 安排上门（时间、人员）或直接办结 → 记录处理结果（结论 + 说明）。
- 每步写入不可变时间线；可查看住户简介并联系家属。

### 公共能力

- 总览看板：可旋转 / 缩放的三维社区模型，点击楼栋与楼层定位告警点，办结后告警点变灰。
- 顶部导航按角色显示可用视图，待办角标实时更新；退出登录销毁服务端会话。

## 七、数据库设计

| 表 | 内容 |
| --- | --- |
| `users` | 账号、PBKDF2 哈希、角色、姓名、所属网格、电话 |
| `sessions` | 随机会话 token、过期时间、最后访问时间（滑动续期 12 小时） |
| `events` | 事件类型 / 等级 / 位置 / 设备依据 / 描述、触发来源、指派、状态、联系 / 上门 / 结果 JSON、办结时间 |
| `timeline` | 每条事件的处置步骤（时间、操作人、角色、动作、备注），外键级联删除 |
| `logs` | 平台级操作日志 |
| `meta` | 事件自增序号等元数据 |

事件状态机：`待接收 → 已接收 → 已联系住户 → 已安排上门 → 已完成`（允许在「已联系住户」后直接办结）。每次状态变更连同时间线与日志在**同一事务**内提交。

## 八、API 一览

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | 公开 | 服务与数据库状态 |
| POST | `/api/login` | 公开 | 校验账号密码，下发 HttpOnly Cookie |
| POST | `/api/logout` | 会话 | 销毁服务端会话 |
| GET | `/api/me` | 会话 | 当前登录用户 |
| GET | `/api/bootstrap` | 会话 | 首屏全量数据（用户、事件、日志、统计、账号） |
| GET | `/api/state` | 会话 | 轮询用轻量快照 |
| GET | `/api/events`、`/api/logs` | 会话 | 事件与日志列表 |
| POST | `/api/events` | 管理员 | 触发模拟事件 |
| DELETE | `/api/events/{id}` | 管理员 | 撤回事件 |
| POST | `/api/reset` | 管理员 | 重置演示数据 |
| POST | `/api/events/{id}/{action}` | 网格员 | 四步处置：`claim`、`contact`、`dispatch`、`resolve` |

服务端序列化时输出驼峰别名（`assignedTo` / `residentId` / `actorName` 等），前端无需感知数据库列名。

## 九、安全设计

- 密码以 PBKDF2-SHA256（12 万轮 + 随机盐）存储，库中无明文；前端不保存账号密码。
- 会话 token 存服务端 `sessions` 表，Cookie 为 `HttpOnly + SameSite=Lax`，退出即删除。
- 所有写接口先校验会话再校验角色：未登录 401、越权 403、参数错误 400。
- 同一 IP 登录失败 5 次锁定 60 秒；请求体限制 64 KB 且仅接受 `application/json`。
- 静态资源白名单使 `anxiang.db`、`*.py`、`*.bat` 等无法通过 HTTP 下载（返回 404）。
- 服务只监听 `127.0.0.1`，不对外暴露。

## 十二、当前边界与后续建议

**这是本机可运行的完整系统，不是公网生产部署方案。**

- 若要对外服务：换 WSGI 服务器 + 反向代理 + HTTPS，补充 CSRF token、持久化限流与日志审计。
- 演示账号需替换为注册流程并修改默认密码，当前账号仅用于本地演示。
- 上传 GitHub：网页建空仓库（不勾选 README / license / gitignore）后执行：

```bash
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

GitHub 已停用账号密码登录，HTTPS 推送需 Personal Access Token 当密码，或改用 SSH key / `gh auth login`。
